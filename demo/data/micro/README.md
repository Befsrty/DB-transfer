# Пример, посчитанный вручную (ТЗ, приложение Д)

Файлы перенесены из приложения Д ТЗ руками, без кода. По ним проверяются правила загрузки
и активации из раздела 4.3.5: и скрипт эталона `demo/tools/make_demo_data.py` (тест
`tests/unit/test_demo_data.py`), и SQL приложения (испытание ПИ-18).

| Файл | Что это |
|---|---|
| `ZSALES_FF_load1.csv` | Загрузка 1: шесть записей, ключ 2/10 повторён, побеждает последняя запись (250,00) |
| `ZSALES_FF_load2.csv` | Загрузка 2: по одной корректировке каждого вида и одна новая позиция |
| `expected_ZSD_A01.csv` | Активные данные ZSD_A01 после двух загрузок (Д.4) |
| `expected_ZSD_A01_changelog.csv` | Журнал изменений ZSD_A01 по обеим загрузкам (Д.1 и Д.3) |
| `expected_ZSD_A02.csv` | Активные данные ZSD_A02 после двух загрузок (Д.4) |

Пустая дата в ожидаемых файлах — пустая строка (в базе NULL). Если файлы расходятся с приложением Д,
ошибка в файлах, а не в приложении: приложение и есть эталон.
